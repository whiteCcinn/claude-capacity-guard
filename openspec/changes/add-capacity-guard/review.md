# Adversarial review and verification

Reviewed on 2026-11-14 against native Claude Code 2.1.325.

| Failure scenario | Result and mitigation |
| --- | --- |
| Waiting hours inside a hook exceeds its 10-second budget and silently falls through | No long hook wait. Save state, abort the main turn, and use a background timer. The streaming gate's error handler also blocks the model request. |
| Five-hour reset occurs while weekly quota remains low | Use all blocking windows and the latest reset; retain prior blocking windows if a partial reading omits them. |
| Parallel main/subagent request gates race | Claim the pause before asynchronous persistence; only one checkpoint, main abort, and continuation are admitted. |
| Continuation starts, then a fresh low reading arrives before its submission promise settles | Release the old claim at main turn start. The new gate can pause again; lifecycle epochs prevent old cleanup from erasing its checkpoint. A regression test first reproduced this failure. |
| Failed disk write leaves a live waiting record that reload might re-arm | Replace the live record with manual state too; tested with a failing disk followed by reload. |
| Duplicate timer callbacks or uncertain prompt delivery | A runtime latch and durable submitting claim prevent repeat dispatch. Refusal, error or reload of an uncertain claim requires manual recovery. |
| User submits a rejected message while waiting | Suspend timer admission during submission; cancel only after acceptance. |
| A background notification arrives | Preserve waiting ownership; it is not treated as a new user instruction. |
| Clear, switch, logout or newer interrupted work | Cancel ownership and timers; live state tombstones prevent stale disk records from reviving on hot reload. |
| Empty or malformed quota readings during a pause | Remain paused. Do not interpret unknown values as zero usage. |
| Restart, headless execution, or unconfirmed abort | Retain a manual checkpoint. Never promise a timer outside a running interactive process. |
| Another process consumes quota after the last reading | Cannot be detected from cached native data; documented. A passed server reset permits a continuation attempt, not a fresh quota guarantee. |

Local automated verification: marketplace and plugin strict validation; strict TypeScript checking against the declarations generated by installed Claude Code; 31 native mock tests covering policy, checkpoint validation, and lifecycle failures. CI had not run remotely at the initial local verification; current status is available in the repository's Actions page.

Native terminal verification: `/capacity` read actual five-hour and weekly quota with the interaction translator loaded. `/capacity cancel` worked. In a separate disposable session, the development fixture supplied low quota and a stubbed main model: the request paused without calling the main model; after the reported reset and buffer, one plugin-attributed continuation ran and rendered `OFFLINE_RESUME_OK`. A subsequent `/capacity` reported no waiting task. Test sessions were exited afterwards.

Installed `capacity-guard@claude-capacity-guard` from this local marketplace at user scope and verified it enabled at version 0.1.0. Persisted options are enabled=true, remaining_threshold=10, reset_buffer_seconds=60 and check_interval_seconds=30. An installed-only session (without `--plugin-dir`) exposed `/capacity` and read native quota alongside the interaction translator. This describes the initial local setup, before the first GitHub publication; no separate tagged release was created by that setup.

Integration follow-up: the continuation origin is asserted as `plugin` in the guard's test. Two isolated native tests against interaction-translator 0.7.0 at source commit `a6ab444d3921a4e0bbe148ab6fcf213f33bcab8a` confirmed both API and CLI translation backends make zero input-translation calls for that continuation. Agent Teams support is explicitly partial: no team-wide stop or per-member resumption is established by the ordinary `agentId` mock tests.

Not established: a real multi-hour wait across an actual account reset, every Claude Code surface/version, or exactly-once side effects in an interrupted external tool. These remain explicit product limits rather than claims inferred from mock tests.
