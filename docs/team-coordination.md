# Agent Teams 队伍协调

[返回 README](../README.md) · [兼容性](compatibility.md)

0.2.0 支持由主会话统一控制的队伍暂停和逐成员恢复。已在 Claude Code 2.1.325、macOS Apple Silicon 的 `in-process` 模式验证真实两名队友的生命周期；测试模型与额度为替身。分屏和其他版本需单独验证。

## 自动发现

`/capacity` 调用 `$.agent.list()`，显示带原生 `teammateId` 标记且未结束的成员数量。普通子代理没有该标记，不会误当队友。暂停时保存原生成员 ID、地址、显示名、活动状态和控制进度，最多 64 名；超限、重复身份或发现失败会转手动处理，不截断队伍后宣称暂停完成。

原生列表可能不再包含已经停止的成员。因此状态命令同时展示当前列表和保存的暂停成员。当前成员为 0 不表示旧暂停记录中的成员已经恢复。

## 暂停顺序

1. 主会话或可观察的队友请求发现低额度，占有唯一的暂停流程并保存记录。
2. 主会话有活动轮次时停止该轮次；请求门禁阻止待暂停成员继续请求和新成员启动。
3. 主会话的后台控制回调对每个活动成员调用 `TaskStop`，逐项记录原生确认。一个成员失败仍会尝试停止其他成员。
4. 再次读取成员列表，捕获停止期间新增的成员；最多执行四轮发现。只有所有需停止的成员均确认停止，才进入额度等待。

原本空闲的成员保留在记录里，但不发送停止或恢复命令。它们在等待期间也受请求门禁约束。一个停止失败、身份不明或列表持续变化都会进入手动状态，避免把部分暂停显示成成功。

这是协调停止，不是同时冻结全部操作系统进程。各个确认之间有时间差，已发送的请求和外部工具可能完成或留下部分结果。停止不会撤销文件、提交或外部操作。

## 恢复顺序

所有已知阻塞窗口解除、主会话空闲后，主会话按记录顺序：

1. 先持久化该成员为 `sending`。
2. 用 `$.session.send({to: {agentId}, text: resumeText})` 向原成员发送配置文本，默认 `continue`。
3. 宿主返回 `isDelivered: true` 后，保存为 `sent`，继续下一名成员。
4. 所有需恢复的成员均确认送达后，保存主会话提交声明，再通过 `$.prompt.submit` 续接主会话。

送达只表示消息已入队，不表示成员已经完成任务，也不会等第一名成员完成后才恢复第二名。恢复沿用原成员身份；本版不重新创建已消失的队友。原来空闲的成员不会额外收到继续消息。

恢复中的成员再次发现低额度时，会撤销旧恢复批次的所有权，把已恢复成员重新纳入停止流程，再等待下一次可用窗口。旧异步回调不能继续唤醒后续成员或清掉新记录。

## 子进程能否自主暂停？

已观察到的成员请求也会进行额度检查，可触发队伍暂停，即使主会话空闲。成员请求被本地门禁拦住后，实际停止和恢复由主会话捕获的控制上下文执行；各成员没有互相竞争的自动恢复定时器。

这项保证依赖宿主能暴露成员事件和控制接口。独立进程是否加载插件、是否共享这些事件及控制能力，取决于执行模式。不能仅凭 lead 安装成功就认定所有分屏都受控；尚未验证的模式见[集成说明](integrations.md#agent-teams)。

## 状态与故障恢复

`/capacity` 按原成员 ID 展示保存状态：

| 状态 | 含义 |
| --- | --- |
| `held` | 原本空闲，不额外唤醒 |
| `pending` / `stopping` | 等待停止 / 停止结果尚未确认 |
| `stopped` | 原生停止已确认 |
| `stop_failed` | 明确拒绝或错误，可以检查后重试 |
| `sending` | 恢复交付已声明，结果尚未确认 |
| `sent` | 恢复消息已入队，不重复发送 |
| `resume_failed` | 明确未送达，可以检查后重试 |
| `uncertain` | 控制或交付结果不确定，不自动重试 |

```text
/capacity
/capacity resume
/capacity cancel
```

`/capacity resume` 只重新接管可确认的团队失败，跳过已送达成员，仍遵守额度阈值。存在 `stopping`、`sending` 或 `uncertain` 时拒绝自动重试，需先检查原生成员和实际进度，避免重复操作。主会话提示交付不确定时也不会自动重试。

`/capacity cancel` 取消后续控制和自动恢复，并列出保存的成员供人工检查。它不会唤醒已经停止的成员。接受新的用户输入也会取消旧协调所有权；如果你要保留并重试现有成员记录，应先使用状态命令和 `/capacity resume`，而非发送普通的新提示。

同进程热重载可接续结果已确认的记录；未完成的控制调用转手动。关闭进程后没有外部守护进程自动恢复，重新打开的记录也要求人工检查。

## 验证与边界

自动测试覆盖拒绝停止后继续停止其他成员、部分恢复不重发、未知交付、取消、请求门禁、新成员、主会话空闲、恢复时额度再次不足，以及发现成员期间的新用户输入。可用[真实队伍测试插件](../dev/team-smoke/README.md)复现停止确认、原身份恢复和主会话续接。

公开 API 参考：[Mods API](https://code.claude.com/docs/en/plugins/mods/api.md)、[原生工具](https://code.claude.com/docs/en/plugins/mods/tools-reference.md)、[Agent Teams](https://code.claude.com/docs/en/agent-teams)。API 随宿主版本变化；本地生成的类型和真实生命周期验证优先。
