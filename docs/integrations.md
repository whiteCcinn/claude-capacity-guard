# 翻译插件、子代理与 Agent Teams

[返回 README](../README.md)

本页描述 0.1.0 的实际边界。额度拦截和完整恢复是两种能力：观察到一个成员的请求，不代表记录了那个成员的任务并能重新唤醒它。

## 自动继续会不会调用翻译？

与 `interaction-translator` **0.7.0** 配合时，自动继续消息不会触发其输入翻译。

守卫通过 `$.prompt.submit({ text: CONTINUE })` 提交消息，不设置 `asUser: true`。原生宿主将其标为：

```json
{"kind":"plugin","name":"capacity-guard"}
```

翻译插件的 `prompt.submit` 钩子只处理 `origin.kind` 为 `composer` 或 `sdk` 的输入，其他来源直接传给后续钩子。因此守卫的固定继续提示即使是中文，也不会为了翻译这段提示而调用 Codex CLI 或翻译 API。不要将它伪装成用户输入来获得原文回显或语言路由功能。

后续 Claude 回复与输入消息是不同阶段：输出仍按翻译插件的 `manual`、`final`、`auto` 或 `conversation` 等设置处理。设置为自动翻译输出时，正常输出翻译仍可能产生调用。

| 内容 | 翻译行为 |
| --- | --- |
| 用户在输入框发送的“继续” | 用户输入，按翻译插件的常规输入逻辑处理；已有目标语言可能在本地跳过 |
| 守卫定时提交的继续指令 | `plugin` 来源，跳过 0.7.0 的输入翻译 |
| 守卫额度检查和定时器 | 不经过翻译后端 |
| 自动恢复后的 Claude 回复 | 按输出翻译配置处理 |

这项兼容性基于[翻译插件 0.7.0 的来源过滤](https://github.com/whiteCcinn/claude-interaction-translator/blob/a6ab444d3921a4e0bbe148ab6fcf213f33bcab8a/plugins/interaction-translator/hooks/register.ts#L332-L342)与本地验证，固定参考提交为 `a6ab444`。未来版本若扩大输入来源范围，需要重新验证。守卫不控制其他插件的行为。

两项独立原生测试已分别验证 `api` 与 `codex-cli` 配置下，该继续文本保持原样且翻译 HTTP / 进程调用数为零。复现方法见[开发文档](development.md#翻译来源互操作检查)。

## 普通子代理

守卫的 `turn.step` 钩子不排除 `agentId`，因此会检查宿主向本钩子暴露的子代理请求。主轮次 ID 已知时，低额度可以触发主任务暂停；并发进入时只建立一条主会话暂停记录。

本版不会逐个记录和重启所有子代理。恢复时只续接主会话，由 Claude 根据已有子任务结果和工具状态决定后续工作。已经在途的请求不能撤回；不向当前钩子暴露事件的其他执行环境不在覆盖范围。

## Agent Teams

Claude Code 可以让队友在同进程中运行，也可以用 tmux / iTerm2 分屏运行。官方说明见 [Agent Teams](https://code.claude.com/docs/en/agent-teams.md)；原生声明与行为会随版本变化。

| 场景 | 额度拦截 | 自动恢复范围 |
| --- | --- | --- |
| 主交互式会话 | 有有效原生读数时检查 | 续接该主会话 |
| 同进程子代理 / 队友，且事件被本钩子观察到 | 检查成员的模型请求 | 没有逐成员恢复队列；只提交主会话继续 |
| 队友运行，但主轮次 ID 未知或主会话空闲 | 可拦截已观察到的低额度请求 | 不能由此推断成员会被自动唤醒；没有主轮次可建立对应的完整恢复流程 |
| tmux / iTerm2 中的独立队友进程 | 每个进程必须实际加载守卫 | 每个进程按自己的会话生命周期处理，不提供全队协调；是否能自动恢复还取决于它是否为交互式会话 |
| 没有加载插件的独立进程 | 不覆盖 | 不覆盖 |

停止主会话不保证其他队友立即停止。共享账号额度也不等于共享一个暂停状态。用户范围安装可方便多个会话发现插件，但仍要检查子进程的设置、策略和实际加载情况，不能仅凭 lead 加载成功就认定全队生效。

**0.1.0 不承诺整队同步暂停、每个成员从原位置自动恢复、队友重建或跨进程原子协调。** 没有完成真实 Agent Teams 生命周期测试；普通并发 `agentId` 模拟测试只能证明请求拦截与主记录防重，不能证明完整 team 支持。

要提供完整支持，需额外实现成员身份与任务记录、每个运行方式的停止确认、逐成员唤醒、lead 空闲时的所有权、成员退出后的清理，以及多个会话恢复请求的协调。本版没有实现这些能力。

## 其他插件与组织策略

其他钩子可以拒绝继续消息、改变后续处理或限制 Mods 加载。守卫看到继续请求被拒绝或无法确认交付时会转为手动，不绕过原生权限要求。`--safe-mode`、禁用钩子的模式、组织管理策略或未启用的插件都可能使守卫不运行。

涉及宿主 API 的结论以[本机版本生成的类型](https://code.claude.com/docs/en/plugins/mods/create.md#get-type-definitions-for-your-version)和实际运行结果为准，不能仅凭公开文档推断所有版本兼容。
