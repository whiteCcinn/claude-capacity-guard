# 翻译插件、子代理与 Agent Teams

[返回 README](../README.md)

本页描述 0.2.0 的实际边界。普通子代理沿用主会话续接；原生 Agent Teams 另外保存成员身份、停止确认及逐成员恢复状态。

## 自动继续会不会调用翻译？

与 `interaction-translator` **0.7.0** 配合时，自动继续消息不会触发其输入翻译。

守卫通过 `$.prompt.submit({ text: runtime.settings.resumeText })` 提交配置文本，默认是 `continue`，不设置 `asUser: true`。原生宿主将其标为：

```json
{"kind":"plugin","name":"capacity-guard"}
```

翻译插件的 `prompt.submit` 钩子只处理 `origin.kind` 为 `composer` 或 `sdk` 的输入，其他来源直接传给后续钩子。因此即使把自动继续文本改为中文“继续”，也不会为了翻译这段提示而调用 Codex CLI 或翻译 API。不要将它伪装成用户输入来获得原文回显或语言路由功能。

后续 Claude 回复与输入消息是不同阶段：输出仍按翻译插件的 `manual`、`final`、`auto` 或 `conversation` 等设置处理。设置为自动翻译输出时，正常输出翻译仍可能产生调用。

| 内容 | 翻译行为 |
| --- | --- |
| 用户在输入框发送的“继续” | 用户输入，按翻译插件的常规输入逻辑处理；已有目标语言可能在本地跳过 |
| 守卫定时提交的继续指令 | `plugin` 来源，跳过 0.7.0 的输入翻译 |
| 主会话发送给原队友的继续指令 | 原生协调消息，跳过 0.7.0 只接受 `composer` / `sdk` 的输入翻译过滤 |
| 守卫额度检查和定时器 | 不经过翻译后端 |
| 自动恢复后的 Claude 回复 | 按输出翻译配置处理 |

这项兼容性基于[翻译插件 0.7.0 的来源过滤](https://github.com/whiteCcinn/claude-interaction-translator/blob/a6ab444d3921a4e0bbe148ab6fcf213f33bcab8a/plugins/interaction-translator/hooks/register.ts#L332-L342)与本地验证，固定参考提交为 `a6ab444`。未来版本若扩大输入来源范围，需要重新验证。守卫不控制其他插件的行为。

集成辅助测试覆盖默认 `continue` 和中文“继续”、`api` 与 `codex-cli` 配置以及 `plugin` / `coordinator` / `peer` 三种来源的十二个组合，验证文本保持原样且翻译 HTTP / 进程调用数为零。协调来源测试验证过滤规则，不代表所有宿主版本都采用相同的来源字段。复现方法见[开发文档](development.md#翻译来源互操作检查)。

## 普通子代理

守卫的 `turn.step` 钩子不排除 `agentId`，因此会检查宿主向本钩子暴露的子代理请求。主轮次 ID 已知时，低额度可以触发主任务暂停；并发进入时只建立一条主会话暂停记录。

本版不会逐个记录和重启所有子代理。恢复时只续接主会话，由 Claude 根据已有子任务结果和工具状态决定后续工作。已经在途的请求不能撤回；不向当前钩子暴露事件的其他执行环境不在覆盖范围。

## Agent Teams

Claude Code 可以让队友在同进程中运行，也可以用 tmux / iTerm2 分屏运行。官方说明见 [Agent Teams](https://code.claude.com/docs/en/agent-teams)；原生声明与行为会随版本变化。

| 场景 | 额度拦截 | 自动恢复范围 |
| --- | --- | --- |
| 主交互式会话 | 有有效原生读数时检查 | 续接该主会话 |
| 普通子代理，事件被本钩子观察到 | 检查请求 | 续接主会话，由主会话处理普通子任务 |
| 同进程原生队友 | 检查成员请求并可触发全队暂停 | 主会话原生停止活动成员，逐成员发送配置文本，再续接主会话；真实两名成员已验证 |
| 队友首先发现不足，主会话空闲 | 拦截请求并建立队伍记录 | 使用主会话后台控制上下文协调；空闲路径有 mock 覆盖 |
| tmux / iTerm2 中的独立队友进程 | 主会话使用原生控制接口；主动本地检查仍需各进程加载插件 | 未完成端到端验证，不能宣称完整跨进程协调；控制失败保留成员记录并转手动 |
| 没有加载插件的独立进程 | 不覆盖 | 不覆盖 |

守卫使用 `agent.list` 的原生 `teammateId` 识别队伍，通过 `TaskStop` 记录停止确认，再用 `session.send` 向原成员身份送达恢复文本。成员逐项确认后才提交主会话继续；原来空闲的成员不额外唤醒。状态、取消及重试流程见[队伍协调](team-coordination.md)。

停止主会话本身不能停止所有队友，故本版额外使用原生成员控制。停止确认仍有时间差，不承诺原子冻结、撤回在途操作、成员任务完成或重建消失的队友。消息送达仅表示入队。

用户范围安装可方便多个会话发现插件，但独立进程是否加载、是否共享事件及控制路径仍需核实。普通并发模拟不能证明分屏支持；真实同进程测试也不能直接推广到其他模式、版本或平台。

## 其他插件与组织策略

其他钩子可以拒绝继续消息、改变后续处理或限制 Mods 加载。守卫看到继续请求被拒绝或无法确认交付时会转为手动，不绕过原生权限要求。`--safe-mode`、禁用钩子的模式、组织管理策略或未启用的插件都可能使守卫不运行。

涉及宿主 API 的结论以[本机版本生成的类型](https://code.claude.com/docs/en/plugins/mods/create.md#get-type-definitions-for-your-version)和实际运行结果为准，不能仅凭公开文档推断所有版本兼容。
