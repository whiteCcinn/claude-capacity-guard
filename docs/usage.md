# 日常使用

[返回 README](../README.md)

## 运行长任务

安装并加载后，正常在交互式 Claude 会话提交任务，无需给模型额外的守卫提示词。例如：“完成这次重构，运行相关检查，再总结尚未解决的问题。”

插件会在每次它能观察到的模型请求前检查额度。低于阈值时，当前主轮次结束，提示行显示阻塞窗口、剩余比例及预计恢复时间。工具可能已经执行，守卫不会回滚文件或外部操作。

保持会话进程运行即可等待。电脑睡眠期间没有代码在执行，唤醒后定时器才有机会继续检查。关机或退出 Claude 后，本版没有其他进程来唤醒它。

## 查看等待状态

```text
/capacity
```

命令显示守卫是否启用、阈值、当前原生快照、当前队伍及保存的逐成员状态。`/capacity status` 与它等价。停止的成员可能暂时不在原生列表中，仍以保存状态跟踪。返回文本会进入会话记录，与原生命令行为一致。

例如五小时剩余 3%、周额度剩余 65% 时，只需要等待不足的五小时窗口；如果周额度也低于阈值，就要等到较晚的窗口重置。检查间隔会让实际提交晚于重置加缓冲的时间。

## 取消和修改任务

```text
/capacity cancel
```

它撤销本次自动继续，不会关闭以后的额度检查。需要暂停使用守卫时，在配置中关闭 `enabled`，或禁用插件。

团队暂停时，取消不会唤醒已停止成员。命令列出保存的成员 ID，供主会话核对后安排。接受新的普通用户输入也会撤销旧协调；若要保留逐成员记录并重试，请先查看 `/capacity` 并使用 `/capacity resume`。

一条被接受的新用户消息会取代旧任务的自动恢复记录；被其他钩子拒绝的消息不会取消旧等待。后台通知和定时任务消息不等同于新的用户意图。若新任务再次遇到低额度，它会建立自己的等待记录。

等待时主轮次已经停止，按 Esc 未必产生可观察的取消事件，不能代替 `/capacity cancel`。清空、切换会话或退出登录也会取消旧的会话等待。

## 自动继续之后

守卫以插件来源提交 `resume_text` 配置的完整文本，默认是 `continue`。可以在原生配置的「自动继续文本」中改成“继续”，或例如：

```text
请先核对已有工具结果和文件改动，从未完成的步骤继续；不要重复已成功的操作。
```

去除首尾空白后按配置内容发送，不拼接旧的长提示。空白或超长值回退到 `continue`。保存配置并重新加载后，当前会话的等待记录使用最新文本。

这是供模型读取的消息，不是外部副作用的事务保证。需要核对既有结果的要求应放在原任务或自定义继续文本里，任务本身仍需具备相应的幂等性和验证机制。外部自动化发送的“继续”或 `continue` 仍按原生输入处理，本配置不会额外匹配传入消息的关键词。

## 手动恢复

重新打开进程、无法确认停止成功、保存失败或继续指令交付不确定时，会显示需要手动继续。先检查会话和实际工作结果，然后发送新的“继续”消息。当前仍然低额度时，守卫可能再次暂停。

原生 Team 处于明确的停止或送达失败时，可以运行：

```text
/capacity resume
```

命令仍然检查额度，跳过已经送达的成员。存在未知交付时会拒绝重发；所有成员送达后，主会话的提交问题也不能通过它重试。先检查实际进度，再决定普通继续消息或成员控制。完整状态解释见[队伍协调](team-coordination.md)。

如果服务器时间已到但恢复请求仍被限流，先查看原生 `/usage` 和守卫 `/capacity`。守卫使用缓存，并不主动刷新账号服务器读数。更多情况见[故障排查](troubleshooting.md)。

Agent Teams 和翻译插件行为见[集成说明](integrations.md)。
